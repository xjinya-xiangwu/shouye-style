# 兽楼处体 · 中文长篇叙事写作 Skill

用「冷开场 + 数据锚定 + 人物驱动」的笔法写中文长篇叙事稿。

这不是一个"写作建议清单"，而是一套**从 42 篇原文、17.1 万字里量化提取出来的、可验收的技法系统**。每条技法都带实测数值，写完之后可以跑脚本核对。

```
$ python scripts/check_draft.py my-draft.md

指标                             实测             目标区间  判定
------------------------------------------------------------------
全文汉字数                        3180      3000 ~ 4500  OK
段落数                           101         90 ~ 110  OK
段落长度中位数                        30          26 ~ 38  OK
短段落(<=15字)占比%                27.7      20.0 ~ 30.0  OK
句长中位数                          18          18 ~ 30  OK
数字密度(处/千字)                  10.06       8.0 ~ 12.0  OK
冒号甩段次数                         12          12 ~ 18  OK
章节数(裸数字分隔)                      6            3 ~ 6  OK
末行字数                           13           4 ~ 30  OK
------------------------------------------------------------------
全部量化指标达标。
```

## 怎么用

工作流共六步：

1. **确认素材**：题材、可核查的数字、场景。没有数字的文章不成其为兽楼处体
2. **选结构**：`references/blueprints.md` 里有 5 种叙事蓝图
3. **写开头**：冷开场，第一句必须落地到具体时间 + 地点 + 画面
4. **写主体**：对照 `references/style-code.md` 的 12 条技法
5. **收尾**：末行 ≤30 字，回到开场的意象
6. **自检**：跑脚本 + 过一遍 `references/self-check.md`

### 12 条技法

| # | 技法 | 一句话 |
|---|---|---|
| 1 | 冷开场 | 第一句落到时间、地点、画面，不铺垫不抒情 |
| 2 | 数据锚定 | 每个论点挂一个颗粒化数字，密度 8–12 处/千字 |
| 3 | 冒号甩段 | 引导句以冒号结尾，换行，引语独立成段（不加引号） |
| 4 | 短段重音 | 关键判断单独成段，≤15 字 |
| 5 | 记者亲历 | 「我去看过」「他跟我说」，让叙述者成为可信赖的信源 |
| 6 | 细节颗粒 | 用可感知的实物替代形容词 |
| 7 | 时间线推进 | 精确时间点切分章节 |
| 8 | 典故引用 | 每篇 1–2 处，引完不解释、不评论 |
| 9 | 克制判断 | 判断权交给数字、引语、典故，作者不宣判 |
| 10 | 环形收尾 | 结尾回到开场的意象，形成物理对照 |
| 11 | 转折词节奏 | 但/却/然而，约 3 处/千字 |
| 12 | 裸数字分章 | 章节之间单独成行写 `1` `2` `3`，不加标题 |

### 5 种叙事蓝图

| 蓝图 | 适用 |
|---|---|
| **A · 环形结构**（默认） | 人物命运、企业兴衰 |
| B · 剖面结构 | 一个事件切入某个行业问题 |
| C · 群像结构 | 主线人物 + 多个个体故事 |
| D · 调查结构 | 从反常数据里挖出问题 |
| E · 对照结构 | 两个主体的命运交错 |

## 自检脚本

```bash
python scripts/check_draft.py <草稿路径>      # 人类可读输出
python scripts/check_draft.py <草稿路径> --json   # 机器可读，便于接入 CI
```

- 全部达标 → 退出码 `0`
- 有未达标项 → 退出码 `1`

短篇（<2500 字）建议按比例折算指标，不要为了凑数注水。

量化指标通过后，还要人工过一遍 `references/self-check.md` 里的**技法清单**和**红线清单**——脚本只能卡住节奏，卡不住事实。

## 边界（重要）

这个仓库只提取**文体技法**，不复制任何原文。使用时请守住四条：

1. **事实**：真实选题中每个人名、数字、时间必须可核查；无法核实的标注来源或删掉
2. **人物**：真实在世人物只写已公开证实的事实；不做动机推定、不做道德审判、不用侮辱性措辞
3. **题材**：涉及公共政策、司法个案、民族宗教、领土主权等议题时，只做技法练习，不产对外成稿
4. **署名**：产出物不得署原作者名义或任何暗示其身份的名义

> 原公众号有多起名誉权诉讼记录。风格可以学，事实标准必须比它更严。

### 语料不公开

用于提取风格的 42 篇原文语料（17.1 万字）**不随本仓库发布**。理由有二：版权，以及没有必要——技法已经被蒸馏成上表和 12 条技法，不需要原文也能用。

## 案例

[`examples/`](./examples) 收录了一个完整实战记录：把一份 4 部分 11 章的 AI Agent 研究报告，
改写成 3180 字的兽楼处体总揽稿。

附有**逐轮修改记录**——第一稿九项指标只有三项达标：

| 指标 | 第一稿 | 终稿 | 目标 |
|---|---|---|---|
| 汉字数 | 1874 ❌ | 3180 ✅ | 3000 ~ 4500 |
| 短段落占比 | 46.2% ❌ | 27.7% ✅ | 20% ~ 30% |
| 数字密度 | 22.41 ❌ | 10.06 ✅ | 8.0 ~ 12.0 |
| 冒号甩段 | 4 ❌ | 12 ✅ | 12 ~ 18 |

里面记了这次踩的最大一个坑：研究报告直接搬过来会变成**提纲**——
数字密度翻两倍，但每个数字都是被罗列的，不是被讲述的。

修法不是删数字，是给每个数字配一句解释和一个具体的「人」。

- 成稿：[`examples/agent-endgame-overview.md`](./examples/agent-endgame-overview.md)
- 过程：[`examples/README.md`](./examples/README.md)

## 关于

- 语料来源：公开渠道抓取，筛选链 75 → 70 → 42 篇（剔除同名标签下的股市日评）
- 提取方式：脚本统计篇幅、段落、句长、数字密度、冒号甩段、开头结尾模式，再结合精读提炼技法
- 所有示例均为原创虚构题材，不指向任何真实主体
